# insertcoin-render

Renders [insertcoin.lol](https://insertcoin.lol) fight replays to MP4, for the download and share buttons on each match page.

This repo is public so the GitHub Actions minutes are free. It holds no app code and no keys. The job opens the public match page in Chromium, records the replay with the CDP screencast, and cuts two files with ffmpeg:

The page plays in slow motion while it is recorded (`src/slowclock.js`, a quarter of the speed by default, env `SLOW`): a runner has no GPU and paints the stage at only ~18–27 frames a second, which lost every drawing that stands for one or two frames. The timestamps are squeezed back afterwards, so both files run at normal speed, at 60 fps:

- `16x9.mp4`, 1920×1080
- `9x16.mp4`, 1080×1920, with the fighters' names above the stage and insertcoin.lol below

The demo music plays under both.

## How a fight gets rendered

1. Every 15 minutes (or on demand) the workflow asks the app whether any fight is waiting (`POST /api/fight-video/pending`). If none is, the run ends there.
2. `render.mjs` claims the next fight (`POST /api/fight-video/claim`). The answer carries the match id, the fighter names, and one signed upload URL per file.
3. It records the fight (in slow motion, see above) from `https://insertcoin.lol/match/<id>?stage=on`, builds both MP4s, and uploads them to the signed URLs.
4. It reports back (`POST /api/fight-video/done`). The app checks that both files are in the bucket before the match page offers them.

A rejudged fight gets rendered again, and the old files are deleted. The app side lives in `lib/fightVideo.ts` in the insertcoin repo.

## Setup

One repository secret, `VIDEO_RENDER_SECRET`: the same value as the Vercel environment variable of that name (at least 16 characters, for example `openssl rand -hex 32`).

GitHub turns off scheduled workflows in a public repo after 60 days without a commit. If renders stop, re-enable the workflow under Actions.

## Local test

```sh
npm ci
npx playwright install chromium
TITLE_A=CORDINARE TITLE_B=ATEL node render.mjs --match <match-id>
```

This writes `out/<match-id>/16x9.mp4` and `9x16.mp4` without uploading anything. It needs ffmpeg with `drawtext`.

## 9:16 candidates and the end card (opt-in)

Today's 9:16 is the 16:9 stage letterboxed across the width (a third of the height), and both files end on the winner's banner without the totals. Two other 9:16 cuts and a score end card can be switched on to compare; with none of these set, both files are cut exactly as above.

| env | values | |
|---|---|---|
| `PORTRAIT` | `legacy` (default), `a`, `b`, `both` | which 9:16 goes into `9x16.mp4`; `both` writes `9x16-a.mp4` and `9x16-b.mp4` and is for `--match` only |
| `ENDCARD` | `1` | appends the end card to both files (2.5 s, a 0.3 s fade from the last frame) |
| `ENDCARD_NOTE` | `0` | leaves out the end card's line "The fight is drawn from the judges' scorecards." |

- **A · compact live stage** (`src/portrait.mjs`): a second recording at a phone viewport (432×608 CSS px at device scale 2.5, so 1080 px wide), where the page lays out a 4:3 stage with its mobile HUD above and the commentary below. The buttons between HUD and stage are cut out. Takes a second slow-motion pass, about as long as the first.
- **B · vertical composition**: from the 16:9 recording, a 4:3 window of the stage that follows both fighters (their drawn bounds, weapons and effects included, sampled on every page frame), with its own HUD above it. If a fighter or an effect ever reaches into the stage's HUD band, the window keeps the full height, and the log says so.
- **End card**: the winner, both sealed totals, the tier and what decided it, read off the page's own end card and shown as the page writes them.

To compare everything for one fight:

```sh
TITLE_A=ATEL TITLE_B=TTRRECHNER node render.mjs --match <match-id> --candidates
```

This writes `16x9.mp4` (with the end card), today's `9x16.mp4`, `9x16-a.mp4` and `9x16-b.mp4` (both with the end card), plus `candidates.json` with the measured layout. The new formats draw all their text as PNGs in Chromium (`src/stills.mjs`), so they do not need `drawtext`; locally, without it, `--candidates` draws today's 9:16 text the same way.
